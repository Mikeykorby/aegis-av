03Protection

Core Shields

Each shield watches a different attack path. Turning one off leaves that path open.
How Aegis protects you. Aegis runs entirely in user mode — there is no kernel driver. That means it detects and quarantines threats the moment a file is written, and can kill a malicious process (e.g. ransomware touching a canary file) — but it cannot pre-empt the raw disk write the way a kernel-backed engine (like Windows Defender's minifilter) can. Web Shield is the one true real-time prevention layer, because it blocks the outbound connection before any file lands. For full kernel-level interception, run Aegis alongside Windows Defender.

How real-time protection works (modular Core Shields)

Like Avast's resident scanner, Aegis defends continuously in the background instead of waiting for a manual scan. Each shield is a separate watchtower over one attack path:

File Shield
Inspects every file the instant it is opened, executed, or modified — the primary active scanner.
Behaviour Shield
Watces running processes for attack patterns — catches zero-day behaviour, not just signatures.
Web Shield
Intercepts network traffic and blocks malicious hosts before a file ever lands (the true prevention layer).
Mail Shield
Inspects email attachments saved from mail clients before they can be opened.

Behind the shields, Aegis correlates local heuristics (YARA-style rules, hash reputation, behaviour scoring) the way Avast's CyberCapture and global telemetry do — but computed locally on this PC, since Aegis has no cloud backend. Newer or unknown files are flagged by behaviour rather than a pre-existing definition.

App Policies (New Apps)

How Aegis treats a brand-new app that wants internet access.

Aegis controls the OS firewall via netsh; it does not install its own packet filter. "Block" mode applies a real deny-outbound baseline rule; "Smart/Strict" enable outbound filtering. True per-connection prompts (Avast's "Ask") require a kernel driver, so "Ask" behaves like Strict here.
